# 搜索发现与组合筛选设计

> 当前：网页测试版 0.1.0-beta.1（2026-10-19），不作为正式版。下文旧版本号、桌面和历史测试结果仅为开发过程记录；当前运行与部署以 README、10 文档及最新验收记录为准。

版本 1.3.0 · 日期 2026-10-18

## 1. 本次确认范围

根据用户提供的手机闲置交易应用参考图，增加历史搜索、可能想搜、默认相关度排序、点击价格切换升降序以及适用于本项目的组合筛选。用户另明确确认增加输入联想和可逐项移除的筛选条件标签。保留夕拾的绿色风格和桌面工作区结构，不复用参考应用的品牌、截图或商品素材。

筛选仅使用真实已有字段：商品分类、价格、成色和发布时间。没有加入信用评分、包邮、品牌认证、AI 智搜或商业服务标签。

## 2. 搜索发现流程

点击搜索框：空输入时显示历史搜索和“可能想搜”；有输入时显示真实在售商品标题联想，约 200ms 延迟请求。回车、搜索按钮、历史词、推荐词、联想项均可以发起搜索。上下方向键可选择联想项，Escape 关闭发现面板。

输入草稿与实际已提交关键词分开保存。只输入不记入历史，也不会在切换排序时偷偷提交尚未确认的输入。每次正式发起搜索恢复“最相关”，保留现有筛选条件。

“可能想搜”从在售标题中匹配常见校园物品词，并以实际在售标题补足；不是基于虚构热度或外部广告。联想同样只使用在售标题，不显示下架 / 售出商品，不读取其他人的搜索历史。

## 3. 历史记录与隐私

历史最多保留 12 条，去首尾及多余空白、按不区分大小写的键去重，最近搜索置顶。可以点击复用、单条删除，或确认后清空当前范围。前端串行保存历史，读取响应带序号，避免快速连续操作时旧响应覆盖新结果。

登录时按当前账号隔离，退出后恢复该设备的游客历史，不自动合并。游客通过随机 HttpOnly Cookie 识别，数据库只保存该随机值的哈希；Cookie 有效期一年。游客历史依赖当前设备 Cookie 和所连接后端数据库；清理 Cookie 或换服务器后不会自动继承。登录历史存于对应服务器账号，切换服务器与本地模式不迁移记录。

本地软件服务端口可能变化，因此不用按端口隔离的 localStorage 保存历史；Cookie 与持久化数据库配合可在退出、重启后保留历史。真实 EXE 自检覆盖账号及游客历史重启保留。

## 4. 相关度与排序

搜索词拆分为空白分隔的词组，所有词组均须出现在标题或描述中。相关度优先级如下，相同级别按商品 ID 倒序稳定排序：

1. 标题与完整关键词相同。
2. 标题以完整关键词开头。
3. 标题包含完整关键词。
4. 所有词组都出现在标题中。
5. 其余满足条件的标题 / 描述匹配。

这是可解释的文本规则排序，没有引入向量检索或 AI 服务。无关键词时“最相关”退化为最新在售，并在界面明确提示。首次点击价格按低到高，再点按高到低，以后交替切换；点击“最相关”或“最新发布”可退出价格排序。排序在服务器完成后再分页，避免只对当前页面排序。

## 5. 筛选交互

桌面右侧抽屉，窄屏底部面板；左侧分组索引定位分类、价格、成色和发布时间。时间支持 1 / 3 / 7 / 14 天内，使用服务端 UTC 时间。价格包含边界，允许 0 元、最多两位小数；最低高于最高时拒绝应用。

打开面板复制当前条件为草稿。关闭 / 点遮罩 / Escape 取消草稿；“重置”只清草稿；“查看结果”才统一应用并回第一页。当前已应用条件显示在排序栏下方，可单独移除，或清除全部筛选；这些操作保留已提交关键词。

## 6. 接口与数据

| 接口 | 行为 |
|---|---|
| GET /api/products | 新增 sort=relevance（默认）、condition、published_within；保留原排序枚举 |
| GET /api/search/suggestions | q 为空返回推荐，非空返回标题联想；limit 1–24 |
| GET /api/search/history | 当前账号 / 设备的 items 与 scope |
| POST /api/search/history | keyword 长度 1–100，规范化、去重、最多 12 条 |
| DELETE /api/search/history | 带 keyword 删除一条，不带则清空当前范围 |

新增 search_history 表：id 主键、owner_key（账号或匿名设备哈希范围）、keyword_key（规范化比较键）、keyword（展示词）、used_at（Unix 微秒）；owner_key 与 keyword_key 联合唯一，范围和时间索引用于读取最近记录。owner_key 为应用层作用域键，没有伪造用户外键关系。启动时增量建表，不修改旧商品 / 用户数据。

API 继续使用同源 Cookie 和写请求 Origin 检查；所有排序、搜索和筛选使用枚举或 SQL 参数绑定。历史响应 no-store，不向客户端返回 owner_key 或匿名 Cookie 值。
