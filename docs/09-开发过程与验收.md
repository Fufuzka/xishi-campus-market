## 3. 后续变更规范

每个变更登记需求编号、理由和验收标准；如导师意见影响数据模型，先更新 Spec、数据库和 API，再实现、执行针对性测试、补证据。提交代码建议一项独立业务变更对应一个清晰提交；分支评审后合入，不将密码、Cookie、运行数据库或虚拟环境加入版本控制。本次未替用户创建远程仓库或伪造 Git 历史。

版本规则：修正文案 / 样式不改变业务为补丁版本；新增兼容接口为次版本；破坏接口或状态语义需要主版本说明。保留评审意见的原文和实际关闭证据，不能先写“通过”再等待导师。

## 4. 答辩演示顺序（约 8–10 分钟）

1. 展示 Spec 范围、架构和数据库 ER 图，说明两个角色和所有权规则。
2. 游客浏览、搜索、分类和价格筛选，打开详情展示联系方式遮蔽。
3. demo 账号登录，上传图片、发布商品，进入我的发布编辑价格。
4. 下架并展示首页不再出现，再重新上架。
5. buyer 账号收藏商品、留言询价；切换卖家回复。
6. 我的收藏取消收藏；卖家确认售出，说明不可恢复和停止留言。
7. 展示手机截图、19 项测试和 11 项浏览器验收结果。
8. 展示部署文件和实际部署状态，提交导师评审表。
