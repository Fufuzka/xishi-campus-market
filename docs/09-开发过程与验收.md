# 开发流程与验证追踪

## 变更流程

功能变更先明确行为、数据边界和验证方式。涉及状态或表结构时更新规格与 API，再实现兼容迁移；提交前运行与影响范围匹配的检查。

一个提交围绕一个明确问题组织。版本控制只保存源码、技术文档和可复现验证材料，不保存运行数据、私人记录或本地打包结果。

## 功能追踪

| 账号和会话 | backend/main.py | tests/test_api.py |

| 消息来源与私信 | backend/campus.py、frontend/experience.js | 私信隔离、来源及导航检查 |

| 云启动 | start.sh、.vscode/preview.yml | Linux 启动矩阵与 cloudstudio-smoke.py |

## 结果记录

自动化结果保存在 evidence/；测试记录应注明环境和覆盖范围。失败修复后复验对应场景，既有通过结果按日期保留，不将历史数量当作当前验证。

接口改动运行相关回归，页面改动执行浏览器检查。部署变更另外验证真实 HTTPS、Cookie、持久化、代理及备份恢复，不能只依据本地结果判断。

## 版本和发布

当前使用测试版本标识。GitHub Actions 负责代码检查，不自动发布网站。每次修改不必创建 Release；需要发布测试节点时使用 beta 标签和 Pre-release，并记录具体变更及验证范围。
