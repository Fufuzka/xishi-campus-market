# 校园交易与平台管理

> 当前多图审核、认证证明权限、消息与交易整合和外观设置以 [14-多图审核与消息布局](14-多图审核与消息布局.md) 为准。

版本 0.2.0-beta.1（测试版） · 日期 2026-10-19

本章说明校园交易和平台管理的功能、权限与状态约束。所有功能通过浏览器使用，优先支持手机 H5；不构建桌面软件，不含在线支付。AI 审核、置换、捐赠等扩展未实现。人工审核不是学校官方身份系统认证。

## 1. 功能规格与验收映射

| 编号 | 功能 | 实际行为 |
|---|---|---|
| CAMP-01 | 商品管理 | 标题、价格、分类、成色、校区、交易方式、图文说明、地点与联系方式；发布、编辑、删除、上下架、售出；发布及编辑后待审核 |
| CAMP-02 | 求购 | 物品名称、预算、期望成色、校区、说明；发布、搜索、分页、查看我的、编辑及结束；卖家从求购发起私聊接洽 |
| CAMP-03 | 学生认证 | 姓名、学号、学院，管理员人工通过／退回；退回后可重新提交；待审或已通过学号唯一 |
| CAMP-04 | 搜索筛选 | 保留历史、联想、推荐、相关度和价格排序；按分类、价格、校区、成色、发布时间组合过滤和分页 |
| CAMP-05 | 互动 | 保留商品留言和卖家回复，新增商品／求购上下文私聊；会话仅双方可读取及发送 |
| CAMP-06 | 线下订单 | 买家发起，卖家填写未来面交时间及地点，双方分别确认完成；支持取消；价格及标题保存快照 |
| CAMP-07 | 平台管理 | 认证审核、商品审核、举报处理、停用／恢复学生、添加／停用／恢复分类及操作记录 |
| CAMP-08 | 手机 H5 | 导航横向滚动；求购、私信、订单、认证和后台适配手机；页面继续显示测试版 |

## 2. 权限与业务边界

只有普通学生和管理员两种角色。游客可以浏览已审核商品及公开求购，注册账号不能指定角色。普通学生认证前可登录、浏览、收藏、留言、举报；认证通过后可发布商品及求购、私聊和发起交易。认证资料仅本人及管理员可见，普通商品、求购、用户摘要不输出姓名、学号、学院、密码哈希或会话令牌。

管理员必须由部署人员显式创建，不自动附赠默认管理员，不提供普通学生自行提权接口。停用学生会使既有会话失效、阻止重新登录，隐藏其商品和求购，取消未结束订单；恢复后需要重新登录。管理员不能在用户管理页面停用管理员。

未审核、退回、被停用卖家的商品不进入公开列表、搜索联想或推荐；非本人及管理员直接访问详情或留言列表返回 404。新商品待审核，编辑后重新待审，不能通过上下架绕过审核。旧商品迁移为待审核，旧用户默认为未认证。

## 3. 架构与模块

前端 Vue 保留同源访问，`frontend/campus.js` 提供校园业务混入，`app.js` 保留商品及搜索逻辑，页面统一在 index.html。FastAPI 的 `backend/main.py` 保留基础业务并安装 `backend/campus.py` 路由。新增业务共用 Cookie 会话、写入 Origin 校验、SQL 参数绑定和 no-store 响应。私信以短轮询自动更新，也可手动刷新，不使用外部消息服务。

```text
浏览器（手机 / 电脑）
  Vue 商品、求购、私信、交易、认证、后台
              ↓ 同源 HTTPS + HttpOnly Cookie
  FastAPI：会话与权限 / 商品搜索 / campus 校园业务
              ↓ 参数化 SQL 与事务
  SQLite：原有表 + 认证字段 / 求购 / 私聊 / 订单 / 举报 / 审计
```

## 4. 数据库增量设计

启动时按 PRAGMA table_info 检查原表字段，缺失时 ALTER TABLE，幂等创建新表及索引；可重复启动，保留账号、商品、收藏、留言、图片及历史。当前为轻量幂等迁移，部署前仍需备份数据库和 uploads。

| 表 | 关键字段及约束 |
|---|---|
| users 新字段 | role、disabled、verification、real_name、student_no、college、verification_note；待审核／通过学号局部唯一索引 |
| products 新字段 | campus、trade_method、review_status、review_note、deleted；默认主校区／当面交易／待审；软删除保留订单 |
| categories | name 主键，active 控制新发布可选项；停用保留历史商品，重启不恢复停用状态 |
| wanted | owner_id、title、description、budget_cents、condition、campus、status、created_at；预算以分保存 |
| conversations | starter_id、recipient_id、product_id 或 wanted_id；同发起人、接收人、上下文唯一 |
| private_messages | conversation_id、sender_id、content、created_at；按会话及消息 ID 索引分页增量读取 |
| orders | product_id、buyer_id、seller_id、price_cents、title、status、meeting_place、meeting_time、buyer_confirmed、seller_confirmed、创建与更新时间 |
| reports | reporter_id、product_id、reason、status、resolution、created_at；同人同商品不重复建立待处理举报 |
| audit_log | actor_id、action、target_id、note、created_at；记录认证、商品、举报、用户、分类管理操作 |

## 5. 订单状态与并发约束

```text
买家发起：待沟通 → 卖家确认时间地点：待交易 → 双方分别确认：已完成
           └──────── 任一方取消：已取消 ────────┘
```

同一商品仅允许一个待沟通／待交易订单，SQLite 局部唯一索引结合 BEGIN IMMEDIATE 防止重复预订。订单保留发起时价格和标题，不含付款。只有卖家可确认未来面交安排；安排确认后不可直接修改，需取消重约。买家、卖家分别确认，全部确认后事务内将订单改为已完成、商品改为售出。第三人无法读取或操作订单。未结束订单会阻止卖家编辑、删除或直接变更商品状态；审核退回、违规下架和停用用户会取消对应未结束订单。完成或取消的订单不可恢复。

## 6. API 接口摘要

所有精确字段、枚举和验证限制见 `docs/openapi.json` 及运行服务 `/docs`。

| 方法 | 路径 | 权限与用途 |
|---|---|---|
| GET / POST | /api/me/verification | 本人查看／提交认证 |
| GET / POST | /api/wanted | 公开分页列表／已认证发布；mine=true 需登录 |
| PUT / DELETE | /api/wanted/{id} | 本人编辑／结束 |
| POST / GET | /api/conversations | 已认证发起上下文私聊／本人会话列表 |
| GET / POST | /api/conversations/{id}/messages | 双方读取／已认证发送；after 增量读取，每批最多 100 条 |
| POST / GET | /api/orders | 已认证发起／本人买卖订单列表 |
| PATCH | /api/orders/{id}/appointment | 卖家确认面交安排 |
| POST | /api/orders/{id}/complete、cancel | 本人确认完成／取消 |
| DELETE | /api/products/{id} | 所有者软删除 |
| POST / GET | /api/reports、/api/me/reports | 登录举报／本人处理记录 |
| GET | /api/admin/overview | 管理待办数量 |
| GET / PATCH | /api/admin/verifications、/api/admin/verifications/{id} | 认证审核列表／处理 |
| GET / PATCH | /api/admin/products、/api/admin/products/{id} | 商品审核列表／处理 |
| GET / PATCH | /api/admin/reports、/api/admin/reports/{id} | 举报列表／处理，可下架商品 |
| GET / PATCH | /api/admin/users、/api/admin/users/{id} | 用户摘要／停用与恢复 |
| GET / PUT | /api/admin/categories | 全分类列表／添加或切换使用状态 |
| GET | /api/admin/audit | 最近 200 条管理记录 |

## 7. 部署与浏览器复验

沿用 README 的启动方法与 08 文档 HTTPS 配置。公网环境不运行 seed，不导入下面的测试数据。管理员创建：

```powershell
python -m backend.create_admin 管理员用户名
```

交互输入密码；已存在的用户名会拒绝创建，不覆盖密码或自动提权。自动化测试可使用临时 MARKET_ADMIN_PASSWORD 环境变量，完成后清理。测试数据库通过 MARKET_DATA_DIR 指向隔离路径；不纳入 Git、Docker 镜像或本地归档。

浏览器验收脚本使用 TEST_ADMIN_USERNAME、TEST_ADMIN_PASSWORD 和 BASE_URL，必须指向隔离演示环境。`browser-test.cjs` 回归原业务，`search-browser-test.cjs` 回归搜索，`campus-browser-test.cjs` 使用学生／卖家／管理员三个独立浏览器会话完成全流程。测试资料及截图均使用虚构学生身份。

## 8. 审查与当前限制

已针对认证绕过、审核绕过、私信及订单越权、重复交易、取消与完成状态、停用账号、已停用分类重启及旧数据库迁移建立测试。管理操作保留审计，不提供任意角色修改。页面不把人工审核冒称官方学籍核验。

公网部署与学校身份系统接入仍需验证。管理列表适用于小规模使用，未增加复杂运营报表和大规模后台分页；私信使用轮询，未提供已读回执或推送。没有 AI 审核及在线支付。这些限制应纳入后续部署评估。
