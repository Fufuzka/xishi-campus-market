## 2. 本机 Python 启动

需要 Python 3.12 和首次下载依赖的网络。项目包含 Vue 和全部示意素材；安装后页面不依赖外部 CDN。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m backend.seed
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

也可执行项目根的 `start.ps1 -Demo`。seed 是可选显式演示步骤，不随服务器启动自动执行。已有用户时 seed 跳过，避免污染现有数据。正式部署省略 seed。

## 3. Docker 本地 / 远程回环运行

```sh
docker compose up -d --build
docker compose logs --tail 100 app
curl http://127.0.0.1:8000/api/health
```

镜像使用非 root 用户，命名卷 market-data 持久化数据库和上传。宿主 8000 仅绑定回环，不直接开放到公网。容器内服务监听 0.0.0.0。不使用 `docker compose down -v`，该命令会删除数据卷。

## 4. 远程 HTTPS 部署

准备 Linux 主机、Docker Compose、已解析到主机的域名；防火墙允许 TCP 80 / 443。上传源码但不要上传本地 data 和公开测试账号。

```sh
export MARKET_DOMAIN=market.example.edu
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
docker compose -f compose.yaml -f compose.prod.yaml logs --tail 100
curl https://market.example.edu/api/health
```

示例域名需替换为真实域名，不能直接使用。Caddy 自动 HTTPS 需要可公开解析和连通的域名；compose.prod 设 `COOKIE_SECURE=1`。Cookie 跟随 HTTPS，前后端同源；不要另用 HTTP 端口登录来测试生产 Cookie。

正式开放注册前应完成审查报告 OPEN-03 / OPEN-04 的身份、审核、限流补充。Docker 与 Caddy 配置为交付配置，尚未在本环境实际构建和签证书。

## 5. 部署后验收

1. 从服务器之外的浏览器打开真实 HTTPS 地址，检查证书和接口健康。
2. 注册测试用户；验证 Cookie HttpOnly / Secure / SameSite 属性。
3. 发布含实物照片的测试商品，另一个账号搜索、收藏、留言、卖家回复。
4. 检查他人不能修改商品、游客看不到联系方式。
5. 重启 app 容器，确认商品、留言、图片仍存在。
6. 做备份并在另一个隔离目录恢复，验证数据完整。
7. 记录地址、时间、执行人及验收结果，并提交导师。

## 6. 数据备份、恢复和升级

简单课程备份：停止 app 服务，将整个 data 目录（或命名卷内容）复制到受限备份位置，再启动。进程运行时可用 SQLite backup API 生成一致性快照并同时备份 uploads；不要直接复制一个正在写入的 db 文件而漏掉 WAL。备份包含联系方式和会话，必须限制访问权限。

恢复时先停止服务，恢复数据库与对应 uploads，再以健康检查和功能抽检确认。升级之前保存源码版本和数据备份；当前仅用建表 SQL 初始化，没有自动迁移系统。回滚不仅要回滚代码，还需核对数据库结构兼容性。

孤立上传：用户先上传照片后放弃发布可能留下图片。定期离线比对 products.image_url 与 uploads；先列出候选并备份，确认无引用且超过保留周期再删除。本项目未提供自动删除任务。

日志：Uvicorn 标准输出，容器使用 compose logs 查看。页面错误不要把 Cookie、密码或真实联系方式复制到公开日志。磁盘、健康接口、错误率、证书到期应由目标服务器监控系统负责。
