# 部署与运维说明

## HTTP 登录与面板环境

`COOKIE_SECURE=1` 只适用于 HTTPS 访问。若访问地址仍是普通 HTTP，浏览器不会在 HTTP 请求中发送 Secure Cookie，可能表现为登录接口成功、切换页面后变回未登录。HTTP 测试环境需设置 `COOKIE_SECURE=0`；启用 HTTPS 后恢复为 1。HTTP 会明文传输登录信息，应尽快迁移至 HTTPS。

宝塔等进程管理面板需要在 **Python 项目的环境变量** 中保存配置，并重新启动该 Python 项目。只在另一个终端执行 `export`，或只重载 Nginx，不会修改现有后端进程的环境。`MARKET_PUBLIC_ORIGIN` 仅接受精确 HTTPS 来源，HTTP IP 访问时不要将 HTTP 地址填入该项，也不要沿用无关的旧预览来源。

前端在登录／注册返回后会再次读取 `/api/me`，确认浏览器确实发送了会话 Cookie 才进入登录状态；失败时提示 Cookie 问题。登录前或登录过程中发出的旧请求，不再用迟到的 401 覆盖新会话。Cookie、数据库和代理配置仍需在实际部署环境核对，不使用浏览器本地存储替代会话校验。

## 在运行中的 Linux 项目创建管理员

在网站实际源码目录执行：

```sh
python3 scripts/create-running-admin.py 管理员用户名
```

辅助命令会寻找当前目录下运行 `backend.main:app` 的进程，复用其项目解释器与 `MARKET_DATA_DIR`，然后调用现有的交互创建命令。系统 Python 只用于读取进程信息，不必另装 FastAPI；输入密码时不显示字符。多 worker 的相同环境会去重；无法读取进程、没有运行实例或有多个不同环境时拒绝猜测，不创建另一份数据库。只适用于 Linux 的常规 Uvicorn 启动方式，容器及其他启动结构请在对应环境使用 `python -m backend.create_admin 用户名`。

账号已存在时不会覆盖密码，也不会将普通用户自动提升为管理员。密码不写入源码；如需单独保存凭据，应放在仓库之外的私密文件中，不随公开代码、汇报或截图归档。

## 1. 运行模式

支持本机 Python、CloudStudio 单端口预览及 Docker Compose / Caddy 配置。本机和 CI 结果不能替代目标环境的 HTTPS、重启持久化与备份恢复验证。

## 2. 本机 Python 启动

需要 Python 3.11 或 3.12 和首次下载依赖的网络。项目包含 Vue 和全部示意素材；安装后页面不依赖外部 CDN。

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
.\.venv\Scripts\python.exe -m backend.seed
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

也可执行项目根的 `start.ps1 -Demo`。seed 是可选显式演示步骤，不随服务器启动自动执行。已有用户时 seed 跳过，避免污染现有数据。正式部署省略 seed。

## 3. Docker 本地 / 远程回环运行

```sh
docker compose up -d --build
docker compose logs --tail 100 app
curl http://127.0.0.1:8000/api/health
```

镜像使用非 root 用户，命名卷 market-data 持久化数据库和上传。宿主 8000 仅绑定回环，不直接开放到公网。容器内服务监听 0.0.0.0。不使用 `docker compose down -v`，该命令会删除数据卷。

## 4. 远程 HTTPS 部署

准备 Linux 主机、Docker Compose、已解析到主机的域名；防火墙允许 TCP 80 / 443。上传源码但不要上传本地 data 和公开测试账号。

```sh
export MARKET_DOMAIN=market.example.edu
docker compose -f compose.yaml -f compose.prod.yaml up -d --build
docker compose -f compose.yaml -f compose.prod.yaml logs --tail 100
curl https://market.example.edu/api/health
```

示例域名需替换为真实域名，不能直接使用。Caddy 自动 HTTPS 需要可公开解析和连通的域名；compose.prod 设 `COOKIE_SECURE=1`。Cookie 跟随 HTTPS，前后端同源；不要另用 HTTP 端口登录来测试生产 Cookie。

正式开放注册前应完善身份校验和登录限流。Docker 与 Caddy 配置需在目标环境完成构建和证书验证。

## 5. 部署后验收

1. 从服务器之外的浏览器打开真实 HTTPS 地址，检查证书和接口健康。
2. 注册测试用户；验证 Cookie HttpOnly / Secure / SameSite 属性。
3. 发布含实物照片的测试商品，另一个账号搜索、收藏、留言、卖家回复。
4. 检查他人不能修改商品、游客看不到联系方式。
5. 重启 app 容器，确认商品、留言、图片仍存在。
6. 做备份并在另一个隔离目录恢复，验证数据完整。
7. 记录地址、时间、执行人及验收结果，供后续运维复核。

## 6. 数据备份、恢复和升级

停机备份：停止 app 服务，将整个 data 目录（或命名卷内容）复制到受限备份位置，再启动。进程运行时可用 SQLite backup API 生成一致性快照并同时备份 uploads；不要直接复制一个正在写入的 db 文件而漏掉 WAL。备份包含联系方式和会话，必须限制访问权限。

恢复时先停止服务，恢复数据库与对应 uploads，再以健康检查和功能抽检确认。升级之前保存源码版本和数据备份；当前由基础 SQL 和兼容迁移函数更新结构，尚无独立的版本化迁移工具。回滚不仅要回滚代码，还需核对数据库结构兼容性。

孤立上传：用户先上传照片后放弃发布可能留下图片。定期离线比对 products.image_url 与 uploads；先列出候选并备份，确认无引用且超过保留周期再删除。本项目未提供自动删除任务。

日志：Uvicorn 标准输出，容器使用 compose logs 查看。页面错误不要把 Cookie、密码或真实联系方式复制到公开日志。磁盘、健康接口、错误率、证书到期应由目标服务器监控系统负责。
